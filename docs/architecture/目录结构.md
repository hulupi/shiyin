# 目录结构与模块职责

## 总体结构

~~~text
shiyin/
├── backend/
│   ├── src/             # API、业务模块、共享类型及音源运行时
│   └── data/            # 本地数据库及运行数据，Git 忽略
├── frontend/            # Vue 前端
├── fpk/                 # fnOS 打包配置与生命周期脚本
├── docs/                # 需求与架构文档
└── scripts/             # 开发启动与 FPK 打包
~~~

## 后端业务模块

| 目录 | 职责 |
| --- | --- |
| catalog | 聚合平台搜索、榜单、公共歌单、歌手和专辑信息 |
| library | 授权音乐目录、递归扫描、标签读取、索引、文件与在线歌曲绑定 |
| playback | 本地优先解析、在线兜底入口、本地音频与远程流传输 |
| lyrics | 同名/指定/内嵌歌词关联、解析、偏移与在线补全 |
| playlists | 自建歌单、在线歌单收藏与导入、曲目顺序 |
| favorites | 歌曲收藏 |
| history | 最近播放记录 |
| downloads | 下载队列、暂停恢复、换源、文件落盘、元数据写入与完成入库 |
| sources | 多音源配置、优先顺序、能力过滤、轮询兜底、超时和冷却 |
| settings | 用户设置、版本化备份与恢复 |

每个业务模块按实际需要建立路由、服务和存储文件，不提前创建大量空实现。扫描规则属于 library，通用任务的启动/停止与重启恢复属于 jobs，避免两处维护相同逻辑。

## 调用边界

- web 通过 server API 访问数据，不能直接访问 NAS 文件或执行音源脚本。
- contracts 只定义协议，不引用前端或后端业务代码，不包含密钥和绝对存储路径。
- platform-adapters 获取搜索与元信息，不负责选择音源或决定本地文件优先级。
- playback 先交由 library 查找已确认绑定的本地文件；不可用时调用 sources 轮询在线音源。
- sources 负责调度，source-runner 执行脚本，source-bridge 提供协议兼容；运行时兼容不等于安全隔离，实际隔离方式需在工程实现时落实。
- downloads 复用 sources 的音源调度；下载完成后通知 library 入库并保存平台歌曲绑定，避免另建不一致的索引。
- 歌词依次读取用户指定本地文件、同名 LRC、内嵌歌词及在线歌词，独立于音频播放请求。
- 飞牛应用生命周期脚本位于 fpk；开发机上的构建和组包流程位于 scripts，职责分开。

## 运行数据

本地 SQLite 数据库默认位于 backend/data/shiyin.sqlite。可通过 SHIYIN_DATA_DIR 指定其他目录，fnOS 安装版使用系统分配的持久化目录。歌曲、歌词和封面保存在用户选择的音乐目录。

## 前端页面拆分

每个一级路由对应 `frontend/src/pages/` 中同名的 Vue 文件。页面的筛选、请求和交互逻辑放在各自的 `<script setup lang="ts">`，样式放在同文件的 `<style scoped lang="scss">`。

| 路由 | 页面 |
| --- | --- |
| `#/home` | `pages/home.vue`（首页） |
| `#/search` | `pages/search.vue`（搜索） |
| `#/charts` | `pages/charts.vue`（榜单） |
| `#/discover` | `pages/discover.vue`（发现歌单） |
| `#/library` | `pages/library.vue`（本地音乐） |
| `#/favorites` | `pages/favorites.vue`（我的收藏） |
| `#/playlists` | `pages/playlists.vue`（我的歌单） |
| `#/downloads` | `pages/downloads.vue`（下载管理） |
| `#/history` | `pages/history.vue`（播放历史） |
| `#/settings` | `pages/settings.vue`（设置） |

路由映射在 `services/router.ts`，`App.vue` 根据页面文件名懒加载。搜索、榜单、发现歌单、自建歌单与下载页面使用 KeepAlive 保留浏览状态；播放器放在路由之外，切换页面不会销毁音频。

通用组件放在 `components/`：`AppSidebar.vue`（侧边栏）、`PageLayout.vue`（页头与内容布局）、`CollectionView.vue`（音乐集合工具栏和列表）、`MusicPlayer.vue`（播放、歌词和队列）、`SongTable.vue`、`TrackActions.vue`、`TrackCover.vue`、`SourceManager.vue`、`ListPagination.vue`、`AppIcon.vue`。各组件的逻辑与 scoped SCSS 都在组件本身。

`AppTheme.vue` 只集中维护文档重置、主题变量和 Element Plus 通用默认值，使用 `:global()`。弹窗和分类菜单挂载到 body，其定制样式仍归各自组件或页面，通过唯一的弹层类名限制 `:global()`；子组件内部节点使用 `:deep()`。原 `src/styles/*.css` 已删除。

`stores/library.ts` 只共享音乐库数据、音质偏好及跨页面的刷新、收藏和扫描操作；页面独有逻辑不放回 App。`useHistoryOrder` 让历史页在浏览时保持顺序，重新打开时取最新排序。

验证命令：

```sh
npm run typecheck --workspace frontend
npm run build
```
