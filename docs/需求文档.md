# 拾音应用需求文档

版本：V1.1 草案  
日期：2026-11-10  
项目目录：`shiyin`  
产品名称：拾音  
文档用途：作为后续界面设计、功能开发、测试和 FPK 交付的依据。本阶段仅形成需求，不代表功能或安装包已经实现。

## 1. 项目概述

开发一款面向飞牛 fnOS NAS 的第三方音乐应用，接入洛雪音乐自定义音源体系，实现多个音乐平台的搜索、播放、下载、榜单和歌单功能，完整展示歌曲封面、歌手、专辑及歌词。

整体视觉参考用户提供的两张截图：深色背景、绿色强调色、左侧导航、主体歌曲列表、底部常驻播放器。参考截图的布局和交互风格，使用本项目自己的名称、图标和界面资产。

最终交付可在目标 fnOS 上安装运行的 `.fpk` 文件，并提供源码、构建脚本、安装说明、升级说明和测试报告。

## 2. 范围与默认假设

### 2.1 已明确的需求

- 运行于飞牛 fnOS，最终以 FPK 安装包交付。
- 使用洛雪音乐相关音源能力，提供多平台音乐服务。
- 必须实现搜索、播放、下载、榜单、歌单。
- 必须显示封面、歌手信息、专辑信息和歌词。
- 界面整体风格参考用户截图。
- 选择或输入 NAS 存储目录后扫描歌曲及歌词，建立本地音乐库；播放优先使用匹配的本地文件。
- 支持多个洛雪音源按顺序轮询尝试，失败时自动使用下一音源兜底。

### 2.2 本文采用的首版假设

以下内容属于建议方案，可在开发前调整，不视为用户已经确认的额外要求。

| 项目 | 首版规划 |
| --- | --- |
| 产品形式 | NAS 后台服务 + 浏览器 Web 界面，从飞牛应用入口打开 |
| 播放位置 | 声音在访问页面的电脑或手机浏览器输出 |
| 下载位置 | 默认保存到 NAS 上用户配置且具有权限的目录；可将已下载文件另存至浏览器设备 |
| 平台范围 | 网易云、QQ、酷我、酷狗、咪咕五个平台，逐个平台验证能力 |
| 用户模型 | 首版单用户资料库，采用应用自身登录保护；不预设飞牛单点登录可用 |
| 系统架构 | 首批适配 x86_64；ARM64 是否发布取决于目标设备和依赖验证 |
| 网络环境 | 优先局域网使用，反向代理访问作为兼容性验证项 |
| 数据维护 | 收藏、歌单、历史、下载记录和设置持久化保存在 NAS |

### 2.3 首版不包含

- 手机原生 App、桌面原生客户端。
- NAS 声卡输出、DLNA、AirPlay、投屏播放。
- 第三方音乐平台账号登录、会员同步、云端个人收藏同步。
- 社交评论、直播、电台、MV、付费内容购买。
- 云端个性化推荐算法；首页可采用精选歌单、榜单和最近播放。
- 与洛雪桌面端的数据同步协议、全量备份格式兼容；可在后续版本单独评估。

## 3. 音源与平台能力边界

### 3.1 接入原则

平台数据适配器负责搜索、榜单、歌单以及歌曲元信息；自定义音源适配层负责按声明能力解析播放地址，必要时补充封面和歌词。两者不能混为一个接口。

洛雪官方仓库说明：音频链接由用户选择的自定义源返回，且链接对应的音频可能不匹配或不可用。因此，本项目必须处理取链失败、链接过期和歌曲不匹配，不承诺任意歌曲永久可用。[洛雪音乐官方仓库](https://github.com/lyswhut/lx-music-desktop)

首版需要选定并记录一个经测试的洛雪自定义源协议基线，列出支持的事件、请求方法、加密工具、平台标识、音质和操作类型。不得仅以“支持 JavaScript 文件导入”宣称兼容所有洛雪脚本。

### 3.2 能力矩阵

| 平台 | 搜索 | 播放取链 | 下载 | 榜单 | 公共歌单 | 封面/歌手/专辑/歌词 |
| --- | --- | --- | --- | --- | --- | --- |
| 网易云 | 目标支持 | 依音源 | 依音源与资源权限 | 目标支持 | 目标支持 | 依平台与音源 |
| QQ | 目标支持 | 依音源 | 依音源与资源权限 | 目标支持 | 目标支持 | 依平台与音源 |
| 酷我 | 目标支持 | 依音源 | 依音源与资源权限 | 目标支持 | 目标支持 | 依平台与音源 |
| 酷狗 | 目标支持 | 依音源 | 依音源与资源权限 | 目标支持 | 目标支持 | 依平台与音源 |
| 咪咕 | 目标支持 | 依音源 | 依音源与资源权限 | 目标支持 | 目标支持 | 依平台与音源 |

“目标支持”表示开发目标，尚未经真实接口验证。发布前必须将此表更新为实测结果和已知限制；某平台关键能力不可用时，应记录为缺陷或明确缩减范围，不能用模拟数据代替验收。

### 3.3 音源管理要求

- 支持用户上传本地 `.js` 音源，展示名称、版本、作者、导入时间及平台/音质能力。
- 支持启用、停用、删除、替换和连通性测试；导入无效脚本时显示原因，不覆盖当前可用配置。
- 未配置音源时仍可浏览和播放本地音乐；需要在线取链时提示配置步骤。
- 音源以受限、可终止的独立运行环境执行，不直接获得宿主文件系统、系统命令或主服务进程权限；不能仅依赖普通 JavaScript VM 作为安全边界。
- 对脚本执行、网络请求设置超时、并发限制和响应体大小限制；禁止通过音源访问 NAS 内部管理服务及云元数据地址。
- 音源崩溃或超时不得导致应用主服务退出；错误日志隐藏密钥及带令牌的完整链接。
- 首版不自动抓取、分发或更新第三方音源；用户管理自己的音源配置。

### 3.4 多音源轮询与兜底（P0）

- 支持同时导入、启用多个音源并调整优先顺序。首版“轮询”定义为按配置顺序逐个尝试，首个可用结果成功后停止，不同时请求全部音源。
- 每次在线播放或下载只选择支持当前平台及操作的音源；先按目标音质遍历适用音源，全部失败后才按用户设置降级音质，再遍历一次。
- 超时、取链失败、空地址、链接不可访问、实际打开音频失败均触发下一音源；返回链接本身不等于播放成功。
- 每个音源同一音质每轮最多尝试一次；链接过期允许当前音源重新解析一次，再进入后续音源。整次解析设总超时（建议 45 秒，可配置），超过后终止并允许手动重试。
- 连续故障音源短暂冷却（建议 60 秒），之后重新参与；停用音源退出新请求，用户可手动测试并恢复。
- 全部音源耗尽时显示汇总失败原因及重试入口；播放器显示实际音源和音质，不暴露敏感链接。
- 同平台同歌曲在多个音源间兜底自动进行；跨平台或不同版本歌曲的替换仍需确认。
- 下载换源时，除非验证为同一资源，否则重新下载，不将不同来源字节直接拼接到旧临时文件。

## 4. 页面与导航

左侧导航建议为：首页、搜索、榜单、发现歌单、我的收藏、我的歌单、本地音乐、下载管理、播放历史、设置。截图中的留言反馈、合作联系、注册入口不作为首版必需项。

| 页面 | 主要内容 |
| --- | --- |
| 首页 | 最近播放、收藏入口、平台榜单和精选歌单入口 |
| 搜索 | 关键词输入、平台筛选、结果列表、加载更多和错误状态 |
| 榜单 | 平台切换、榜单卡片、榜单详情、播放全部 |
| 发现歌单 | 平台歌单列表、可用分类、歌单详情 |
| 歌手详情 | 名称、头像/简介（可获取时）、相关歌曲、专辑 |
| 专辑详情 | 封面、名称、歌手、发行信息（可获取时）、曲目 |
| 我的收藏/歌单 | 收藏歌曲、自建歌单、排序与批量管理 |
| 本地音乐 | 存储目录、扫描状态、歌曲/歌手/专辑浏览、歌词关联、在线歌曲匹配管理 |
| 下载管理 | 排队、下载中、已完成、失败任务及 NAS 保存位置 |
| 播放历史 | 按最近播放排序，支持重新播放、移除和清空 |
| 设置 | 多音源顺序及兜底、播放音质、存储/扫描目录、下载目录、任务并发、数据备份、登录与关于 |
| 播放详情 | 大封面、歌曲信息、同步歌词、播放控制 |

页面切换不应重建播放器或中断当前播放。浏览器刷新后恢复队列及上次进度，等待用户点击继续，不强制自动发声。

## 5. 功能需求

### 5.1 搜索（FR-01，P0）

- 支持歌曲名、歌手名、专辑名关键词搜索；首版结果以歌曲为主。
- 提供“全部、网易、QQ、酷我、酷狗、咪咕”平台筛选。
- 支持回车搜索、清空输入、搜索历史记录和删除历史。
- 全平台搜索并行请求，各平台独立分页；单个平台失败不阻塞其他结果，并显示失败来源及重试入口。
- 新搜索应取消或忽略旧请求结果，避免列表被过期请求覆盖。
- 同名歌曲默认保留来源平台，不按名称强制去重；歌曲主键由平台和平台歌曲 ID 共同组成。
- 列表展示序号、封面、歌曲名、歌手、来源、可用音质、专辑、时长；支持播放、下一首播放、加入队列、收藏、加入歌单和下载。
- 未知音质不得标注为 FLAC 或 Hi-Res；时长缺失显示占位。

### 5.2 播放与队列（FR-02，P0）

- 支持播放/暂停、上一首/下一首、进度拖动、音量、静音。
- 支持列表循环、单曲循环、随机播放、顺序播放；界面显示当前模式。
- 支持立即播放、追加队列、下一首播放、移除、清空和调整队列顺序。
- 点击“播放全部”以当前列表创建队列并开始第一首；替换非空队列时给出明确行为提示。
- 音质选择以当前音源实际支持为准，目标包括 128K、320K、FLAC、Hi-Res；高音质不可用时按用户设置询问或降级，并标明实际播放音质。
- 所有播放入口统一遵循：匹配的可用本地文件 → 按顺序轮询在线音源 → 汇总失败。具体规则见 3.4 和 5.10；跨平台换曲需确认，不以同名自动替换。
- 浏览器不支持的格式必须明确提示；是否提供转码作为技术验证后的范围决策，不默认所有浏览器原生播放 FLAC。
- 队列连续失败达到阈值（默认 3 首）暂停并提示，避免无限跳歌。
- 浏览器切换应用页面不影响播放；后台标签页、锁屏行为受浏览器限制，需在兼容性报告说明。

### 5.3 封面、歌手和专辑（FR-03，P0）

- 歌曲列表、播放器、播放详情、歌单和榜单展示对应封面，失败时使用统一占位图。
- 歌手支持多人显示；可获取时进入歌手详情，显示简介、相关歌曲和专辑。
- 专辑支持进入详情查看曲目、歌手及可用发行信息。
- 数据缺失时明确显示“暂无信息”，不生成虚构内容；不具备详情能力的平台禁用跳转并说明。
- 图片懒加载与缓存，长标题省略并可查看完整内容。

### 5.4 歌词（FR-04，P0）

- 歌词优先级为：用户指定的本地歌词 → 同目录同名 `.lrc` → 音频内嵌歌词 → 在线歌词；本地歌词损坏时提示并尝试下一项，不覆盖原文件。
- 支持普通 LRC 解析、当前行高亮、随播放进度滚动、点击歌词跳转；无时间轴的内嵌歌词只展示文本。
- 用户手动滚动后暂时停止自动跟随，提供“回到当前歌词”。
- 支持歌词时间偏移调节并按歌曲保存，范围建议为 ±10 秒。
- 翻译、罗马音、逐字歌词按接口能力展示；首版不强制全部音源具备这些数据。
- 无歌词、纯音乐、解析失败有独立状态；歌词请求不得阻塞播放。

### 5.5 榜单（FR-05，P0）

- 支持切换平台，显示榜单名称、封面和可获取的更新信息。
- 详情布局参考截图二：上方封面、榜单名称、来源、简介、播放全部和刷新；下方歌曲列表。
- 支持单曲播放、整榜入队、收藏歌曲及下载。
- 缓存榜单内容，手动刷新时保留旧内容并显示刷新结果；不将本地缓存时间误标为平台更新时间。

### 5.6 公共歌单与我的歌单（FR-06，P0）

- 支持平台公共歌单浏览、分页、详情及曲目获取；分类依实际平台能力开放。
- 支持输入可识别的平台歌单 URL 或 ID 导入公开可访问的曲目；明确区分“收藏在线歌单”和“复制到我的歌单”。
- 导入失败、不公开、空歌单、部分曲目缺失时给出具体状态及导入数量。
- 我的歌单支持新建、重命名、修改描述、删除、添加/移除曲目、调整顺序、批量操作。
- 同歌单内按平台与歌曲 ID 去重；跨平台歌曲保留独立条目。
- 删除歌单需确认，只删除歌单记录；不删除 NAS 已下载文件。

### 5.7 收藏与历史（FR-07，P0）

- 支持收藏/取消收藏歌曲、收藏公共歌单，并持久化。
- 实际开始播放后记录历史，连续重复播放同曲更新最近时间；保留上限建议 1000 条。
- 支持历史单条删除和清空，清空需确认。
- 收藏、歌单和历史不得存储短时有效的播放链接作为长期播放依据，播放时先检查本地匹配，没有可用本地文件再重新取链。

### 5.8 下载管理（FR-08，P0）

- 支持单曲、选中曲目、整张歌单/榜单批量创建下载任务。
- 用户可选择音质和 NAS 保存目录，展示任务数、预计音质及目标位置；大批量任务提交前确认。
- 下载状态包括排队、解析、下载中、暂停、完成、失败、取消；显示进度、速度、大小（可获取时）和失败原因。
- 支持暂停/继续、取消、失败重试、清除记录；默认并发 2，设置范围建议 1–5。
- 仅服务端与上游均支持 Range 时提供续传；否则继续操作会重新下载，并明确提示。
- 文件名默认“歌手 - 歌曲名”，清理非法字符和路径穿越，重名支持跳过或自动编号，覆盖需要明确选择。
- 未完成文件使用临时扩展名，成功后原子重命名；重启后恢复队列并检查残留临时文件。
- 按容器格式能力写入歌名、歌手、专辑和封面；支持可选 `.lrc` 歌词及封面旁文件。写入失败保留有效音频并提示元数据失败。
- 启动前检测目录权限和剩余空间，磁盘不足时停止新任务并提示。
- 下载完成后立即将歌曲及已保存歌词加入本地索引，并记录平台歌曲 ID 与本地文件关联，后续播放直接命中本地。已存在匹配文件时展示位置和音质，默认跳过重复下载，允许明确选择补下其他音质。
- 清除任务记录不删除文件；删除已下载文件为独立操作，展示路径并确认。

### 5.9 设置、备份和访问保护（FR-09，P0）

- 首次使用设置应用管理员密码，后续通过应用会话访问；禁止默认公开下载目录或音源接口。
- 设置播放默认音质、音质降级策略、多音源顺序、超时及冷却、存储扫描目录、默认下载位置、并发、歌词偏移和缓存容量。
- 支持导出/导入本应用版本化 JSON 备份，包含收藏、歌单和设置；音源脚本、密钥、登录信息及音频文件默认不包含。
- 导入前校验版本和结构，并选择合并或替换；替换前生成备份。
- 关于页展示版本、构建信息、开源声明及实际适配平台。

### 5.10 存储目录扫描与本地优先（FR-10，P0）

- 支持选择目录或手动输入 NAS 绝对路径，并在保存前验证存在性及读取权限；下载目录额外验证写权限。目录选择器只展示已授权 NAS 路径，不使用浏览器设备路径代替 NAS 目录。
- 支持多个音乐目录，其中可指定一个为默认下载目录；目录可以只读，扫描不得改写、移动或删除用户原文件。
- 保存新增目录后自动启动后台递归扫描，支持手动增量扫描、全量重建和取消；展示扫描进度、已发现歌曲数、歌词数、失败数与完成时间。
- 目标扫描格式包括 MP3、FLAC、M4A/AAC、WAV、OGG/Opus；可入库与当前浏览器可播放分别标记，不能仅凭扩展名认定可播放。忽略未完成下载、临时文件及隐藏系统目录。
- 读取音频标签中的歌名、歌手、专辑、时长、音质和内嵌封面；缺失时尝试“歌手 - 歌名”文件名解析，无法确定的字段保留未知并允许手动修正。
- 扫描同目录同名 `.lrc`（不区分扩展名大小写）并自动关联，例如 `歌手 - 歌名.flac` 与 `歌手 - 歌名.lrc`；其他命名支持用户手动关联。兼容 UTF-8 和常见中文编码，失败时明确提示。
- 本地音乐页面支持按歌曲、歌手、专辑浏览与搜索，以及播放、入队、收藏、加入歌单、查看文件位置和手动关联在线歌曲。
- 增量扫描识别新增、修改、删除文件，避免重复入库；目录重叠时同一规范路径只入库一次。单文件损坏不阻塞整次扫描。
- 目录离线或权限丢失时标记暂不可用，保留索引和收藏，不将整库当作已删除；完整扫描确认文件移除后标记失效，不静默删除用户歌单条目。
- 在线歌曲匹配本地文件优先采用下载记录中的平台+歌曲 ID 或用户手动绑定。历史文件根据歌名、歌手、专辑、时长及版本信息生成候选；同名、翻唱、现场版或多个候选不得直接自动替换，确认后保存关联。
- 从搜索、榜单、歌单、历史或队列播放时，先检查已关联本地文件的存在性、可读性及格式。可用则直接播放并标注“本地”；默认不因在线音质更高而绕过本地，允许用户手动选择在线播放。
- 本地文件不存在、损坏或格式不可播放时，说明原因；有已确认的平台关联则进入在线音源兜底。只有本地信息且无在线关联时提供搜索匹配入口，不盲目换歌。
- 本地可用时无需调用在线取链；本地歌词齐全时无需请求在线歌词。断网且浏览器仍能访问 NAS 服务时，可播放本地音频和歌词。
- 本地音频由带鉴权的服务流式提供，支持进度拖动所需的范围读取；客户端使用文件 ID，不暴露任意文件读取接口。符号链接解析后也必须处于授权目录范围内。
- 移除扫描目录仅移除索引范围及标记关联失效，不删除真实文件；播放前重新检查目录授权，防止继续使用已取消授权的路径。

## 7. 技术与数据约束

### 7.1 建议结构（待技术验证）

采用 Web 前端、NAS API 服务、平台适配层、独立音源运行服务、音源轮询调度、本地扫描索引服务、下载任务服务和持久化数据库分层。首版数据库可采用 SQLite；具体语言、框架、容器或原生服务形式在 FPK 技术验证后确定。

浏览器通过服务端统一获取平台数据。需要代理音频时支持流式传输和 Range，避免整首音频缓存在主进程内存中；对代理目标进行授权和校验，不能形成开放代理。

### 7.2 核心数据

| 对象 | 关键字段 |
| --- | --- |
| Song | 内部 ID、平台、平台歌曲 ID、名称、歌手数组、专辑、时长、封面、可用音质、原始平台标识 |
| Playlist | ID、类型（本地/在线收藏）、名称、描述、封面、来源、平台歌单 ID、曲目顺序、更新时间 |
| Queue | 曲目、当前索引、模式、最近播放位置；各浏览器会话独立 |
| Favorite / History | 歌曲引用、收藏时间/最近播放时间 |
| Source | 名称、版本、平台能力、音质能力、启用状态、优先顺序、失败次数、冷却状态、脚本存储引用 |
| LibraryDirectory / ScanJob | 授权目录、读写权限、递归规则、扫描状态、进度、最近成功扫描时间 |
| LocalTrack / LocalLyric | 文件 ID、所属目录、规范路径、大小、修改时间、标签、格式、歌词路径/内嵌内容、可用状态 |
| LocalSongBinding | 平台与歌曲 ID、本地文件 ID、匹配依据、用户确认状态、多音质版本 |
| DownloadTask | 歌曲、目标音质、实际音质、目标路径、状态、已下载字节、错误、重试次数 |
| Settings | 用户偏好、目录配置、缓存设置、数据格式版本 |

收藏和歌单保存在 NAS；不同浏览器默认共享单用户资料库，播放队列及播放状态分别维护，避免一台设备操作打断另一台。

## 8. 非功能需求

- 稳定性：单平台故障、单音源超时、单任务失败不能造成整体服务不可用。
- 性能目标：在约定的测试 NAS、千兆局域网和桌面浏览器中，应用页面可操作时间不超过 3 秒；外部搜索/取链耗时单独记录，不计入静态页面加载指标。
- 请求控制：外部请求默认 15 秒超时，可配置；每个平台限流，限制重试并提供取消，不能无限重试。
- 列表性能：500 首曲目列表滚动无持续明显卡顿，必要时虚拟滚动；批量任务不阻塞播放控制。
- 容量：支持至少 100 个自建歌单、合计 10000 条歌曲引用；缓存和日志具有容量或轮转限制。
- 播放验证：连续播放至少 2 小时无应用自身导致的中断；外部音源故障单独记录。
- 安全：登录鉴权覆盖所有管理接口；防止越权文件访问、路径穿越、脚本逃逸和任意 URL 代理；密码采用可靠的单向散列。
- 日志：记录平台、操作、耗时和错误码，不记录密码、完整音源脚本或敏感取链参数。
- 浏览器：验收时记录 Chrome、Edge、Safari 的具体版本和音频格式支持；不能只以页面打开作为播放兼容性通过。

性能目标需在开发阶段确定 NAS 型号、内存和系统版本后复核，不代表已取得的测试结果。

## 9. FPK 打包与飞牛集成

### 9.1 安装要求

- 按飞牛官方开发规范制作应用元信息、图标、入口、权限声明、安装向导及生命周期脚本。
- 在应用中心可安装、启动、停止、重启和卸载；启动成功后提供 Web 访问入口及健康检查。
- 安装时选择或配置数据目录、音乐扫描目录、下载目录和服务端口；检测端口冲突和目录权限。
- 将程序、持久化数据、缓存和下载目录区分；升级不得将用户数据覆盖到程序目录。
- 所有运行依赖必须随包提供或由明确声明的机制安装，不能隐含依赖开发机已有环境。
- 默认以最小权限运行；下载访问范围限制在用户授权目录内。

### 9.2 生命周期

- 启动：校验配置、执行可回退的数据迁移、恢复任务状态、启动服务。
- 停止：停止接收任务、保存队列、释放端口并退出子进程。
- 升级：备份配置与数据库，验证旧数据可用；失败时提供恢复步骤。
- 卸载：明确区分删除程序和删除用户数据，默认保留下载音频；具体向导行为按 fnOS 能力实现并验证。
- 重启 NAS：根据应用自启动配置恢复服务，不能恢复为未授权的自动发声。

### 9.3 构建与交付

提供可重复的构建步骤、锁定依赖和版本号，使用飞牛打包工具生成版本化 `.fpk`；具体命令、目录字段、签名与发布要求以实施时官方文档为准。本次检索未能直接读取官方文档正文，因此本文不将未核实的 SDK 字段写为固定要求。[飞牛开发者文档入口](https://developer.fnnas.com/docs/)

每个发布包附架构、适用 fnOS 版本、校验值和变更记录。ARM64 如纳入交付，应单独构建或验证通用包机制，不能仅修改包名宣称兼容。

最终交付清单：

1. 已在目标设备完成安装验收的 FPK 文件。
2. 完整源代码、依赖锁文件、构建和打包脚本。
3. 安装、音源配置、下载目录设置、升级与卸载说明。
4. 平台/音源/音质/浏览器兼容性矩阵及测试报告。
5. 数据备份恢复说明、已知问题、第三方依赖与许可证说明。

## 11. 实施阶段

1. **兼容性验证**：确定目标 fnOS、架构和打包方式，验证五个平台元数据、自定义源协议、浏览器播放与下载闭环，输出能力矩阵。
2. **界面与核心播放**：实现参考风格、搜索、歌曲信息、底部播放器、队列和歌词。
3. **音乐管理**：完成榜单、公共歌单、自建歌单、收藏、历史、目录扫描、本地优先、多音源兜底及下载入库。
4. **飞牛集成**：完善权限、数据持久化、安装向导、升级迁移和 FPK 构建。
5. **发布验收**：真实设备测试、错误场景测试、视觉验收，交付安装包与说明。

P0 为上述首版闭环必需项；P1 包括真实音频可视化、定时停止播放、更多歌词格式和额外架构；P2 可评估多用户、平台账号同步、DLNA 等扩展。不将 P1/P2 作为首版默认承诺。
