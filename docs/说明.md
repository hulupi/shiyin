# 拾音运行与打包说明

需要 Node.js 22.18 或更新版本。除特别说明外，命令都在仓库根目录执行。首次使用或锁文件更新后，先安装根目录依赖。

```sh
npm ci
```

## 网页版

开发时同时启动前端和后端：

```sh
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。Vite 会把 API 请求代理到本机后端。

构建并运行：

```sh
npm run build
npm start
```

前端产物位于 `frontend/dist/`。后端会同时提供页面和 API，默认访问 `http://127.0.0.1:3180`。需要更改监听地址、端口或数据目录时，在启动环境里设置 `HOST`、`PORT`、`SHIYIN_DATA_DIR`，参考 [环境变量示例](../.env.example)。

## 飞牛 fnOS（FPK）

准备当前系统可运行的 fnpack。Windows 默认读取 `backend/data/fnpack.exe`，Linux 和 macOS 默认读取 `backend/data/fnpack`。也可以用环境变量 `FNPACK_PATH` 指定工具路径。

```sh
npm run package:fpk
```

产物位于 `fpk/shiyin-<版本>-all.fpk`。在飞牛应用中心手动安装并启动拾音，然后从飞牛桌面打开，网关入口为 `/app/shiyin/`。工具版本、目录授权与安装验证见 [FPK 打包与安装](fpk打包.md)。

## Windows 桌面版

桌面端独立安装依赖。本地调试时先构建运行时，再启动 Electron：

```powershell
npm --prefix desktop ci
npm --prefix desktop run build:runtime
npm --prefix desktop start
```

修改前后端后重新构建运行时。重启之前，从托盘右键选择「退出」。

生成 Windows x64 安装包：

```powershell
npm --prefix desktop run package:win
```

产物位于 `desktop/dist/local/Shiyin-Local-Setup-<版本>-x64.exe`。如果 Electron 压缩包下载超时，并且 `desktop/node_modules/electron/dist/electron.exe` 已存在、版本与桌面端依赖一致，可以直接复用本机已解压的 Windows x64 Electron：

```powershell
npm --prefix desktop run package:win -- --config.electronDist=node_modules/electron/dist
```

如果 `npm ci` 报 `EPERM unlink` 且指向 Rolldown 的 `.node` 文件，先停止正在使用该仓库的 Vite 开发服务，再重跑 `npm ci`。

## macOS 桌面版

### 准备环境

在 Mac 上使用 Node.js 22.18 或更新版本。打开终端，进入拾音仓库根目录，确认当前目录下有 `package.json` 和 `desktop/`，然后安装两套依赖：

```sh
node -v
npm ci
npm --prefix desktop ci
```

首次构建需要联网下载 npm 依赖、Electron 和打包工具。打包脚本会构建前端和本地服务，将它们一起装入应用，并从 `fpk/ICON_256.PNG` 生成 macOS 应用图标。

### 生成 DMG

按**要安装这款应用的 Mac** 选择架构。在「 → 关于本机」里，显示 Apple 芯片的选 `arm64`，显示 Intel 处理器的选 `x64`。

**Intel Mac**

```sh
npm --prefix desktop run package:mac -- --x64 --config.mac.identity=-
```

**Apple 芯片 Mac**

```sh
npm --prefix desktop run package:mac -- --arm64 --config.mac.identity=-
```

以上命令使用临时签名，适合本机试装。正式对外分发时，去掉 `--config.mac.identity=-`，使用钥匙串中的 Developer ID Application 证书签名，并配置 Apple 公证。打包脚本不会自动发布产物。

### 找到安装包并验证

DMG 生成在 `desktop/dist/local/`。文件名中的版本来自 `desktop/package.json`，例如 `Shiyin-Local-Setup-0.1.15-x64.dmg`。有多个同名旧包时，核对文件修改时间和架构后再安装。以下以 Intel 版为例，版本号按实际产物替换：

```sh
hdiutil verify desktop/dist/local/Shiyin-Local-Setup-0.1.15-x64.dmg
```

双击 DMG，把「拾音」拖到「应用程序」。升级前按 `⌘Q` 完全退出旧版，再替换应用并从「应用程序」打开。安装后可检查可执行文件架构，Intel 版应显示 `x86_64`，Apple 芯片版应显示 `arm64`：

```sh
file "/Applications/拾音.app/Contents/MacOS/拾音"
codesign --verify --deep --strict "/Applications/拾音.app"
```

试装时确认 Dock 显示拾音图标、屏幕顶部菜单栏图标没有被裁切，以及窗口左上角有原生三色按钮。红色按钮关闭窗口，仍可在 Dock 点拾音重新打开。

### 下载超时

如果构建卡在下载 Electron，可以临时指定 Electron 镜像后重试，例如 Intel 版：

```sh
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm --prefix desktop run package:mac -- --x64 --config.mac.identity=-
```

如果日志已进入 `building target=DMG`，先确认这一轮是否真的生成了新的 DMG。应用打包和 DMG 生成是两个步骤，目录里已有旧 DMG 时，仅凭文件存在无法判断这一轮是否成功。

## Android

Android 版将 Vue 页面打入 APK，音源解析和音频拉流由手机完成，无需配置 `SHIYIN_ANDROID_SERVER_URL`。需要 Node.js 22.18 或更新版本、JDK 21，以及 Android SDK Platform 36。也可以使用 Android Studio 配置构建环境。

### 本机 PowerShell 打包（已验证）

在仓库根目录 `E:\www\wb\codex\fn-music` 执行。以下是这台电脑现有的 JDK、SDK 路径，2026-11-24 已成功生成调试 APK：

```powershell
Set-Location E:\www\wb\codex\fn-music
$env:JAVA_HOME = 'C:/Users/admin/AppData/Local/Temp/shiyin-build-zulu/zulu21.48.17-ca-jdk21.0.10-win_x64'
$env:ANDROID_HOME = 'C:/Users/admin/AppData/Local/Temp/shiyin-build-sdk'

# 首次使用或 package-lock.json 更新后执行
npm ci
if ($LASTEXITCODE -ne 0) { throw '安装依赖失败' }

# 构建安卓前端并同步到 Android 工程
npm run android:sync
if ($LASTEXITCODE -ne 0) { throw '前端构建或 Android 同步失败' }

# 使用本机已缓存的 Gradle 依赖生成调试包
.\android\gradlew.bat -p android :app:assembleDebug --offline
if ($LASTEXITCODE -ne 0) { throw 'Android 打包失败' }
```

已安装依赖且锁文件未变时，可以跳过 `npm ci`。修改前端后必须重新执行 `npm run android:sync`；只修改原生 Java 代码时，可以直接执行 Gradle 打包命令。

看到 `BUILD SUCCESSFUL` 表示构建成功，安装包输出到：

```text
E:\www\wb\codex\fn-music\android\app\build\outputs\apk\debug\app-debug.apk
```

核对安装包修改时间，避免误用旧包。此包为调试 APK，正式分发需配置发布签名并生成 release APK 或 AAB。编译通过不代表后台连续播放已经通过手机实测。

### 环境与常见问题

- 报 `JAVA_HOME is not set`：在当前 PowerShell 中重新执行上面的两个环境变量赋值；它们只对当前终端会话生效，无需重装 Java。
- 本机 JDK、SDK 位于临时目录，系统清理后可能失效。可用 `Test-Path "$env:JAVA_HOME/bin/java.exe"` 和 `Test-Path "$env:ANDROID_HOME/platforms/android-36"` 检查。路径失效时，改成实际安装的 JDK 21 和 SDK 路径。
- `--offline` 报依赖未缓存：确认网络可用，去掉 `--offline` 后重新运行 Gradle 命令。首次配置环境也可能需要联网下载 Gradle、依赖或 SDK 组件。
- 希望用 Android Studio 构建或连接手机调试：先执行 `npm run android:sync`，再执行 `npm run android:open`，在 Android Studio 中选择设备并运行。

其他电脑请自行配置 JDK 21、Android SDK 36，并将示例环境变量改为对应路径。更多信息见 [Android 客户端说明](../android/README.md)。
